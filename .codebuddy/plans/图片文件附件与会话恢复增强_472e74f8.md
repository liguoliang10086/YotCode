## 用户要求

用户希望在现有终端 AI 编程助手中补齐三类能力：

1. 用户主动把截图/图片、文件发送给大模型（当前仅模型自己调用工具读图片，且并非所有供应商都可见）。
2. 提供四种发送入口：无头模式命令行附加文件、输入框粘贴剪贴板截图、@文件智能识别（图片走附件、文本走原文）、拖放/粘贴文件路径自动识别为附件。
3. 会话恢复增强：不带 id 的 `resume` 操作应弹出会话列表选择器，而不是直接取最近一条会话。

## 产品概述

项目是一个 Python 终端 AI 编码助手，数据层早已定义图片块并能序列化到会话记录，两个供应商的协议转换也已支持用户消息中的图片。真正的缺口在"输入端"：从输入框到 Agent 的整条链路只接受纯文本，UI 也没有任何附件处理。本需求把这条链路完整打通，并让会话恢复体验与主流 CLI 一致。

## 核心功能

- 四种附件入口统一产出结构化内容块，随用户提问一起发送给模型。
- 输入框展示已附加的图片/文件筹码，可在发送前移除。
- 图片按大小与类型做安全校验，超限时给出可读提示而非崩溃。
- 会话文本、图片附件都能完整存入历史并在恢复后回放。
- 不带 id 的会话恢复弹出可筛选的选择器，支持恢复数天前的会话。

## 1. 技术栈与决策

- 现有栈：Python 3.10+、Textual 8.x（TUI）、Rich（渲染）、httpx（API）。沿用现有分层：types（数据模型）→ agent（编排）→ providers（协议转换）→ ui（交互）。
- 新增依赖：Pillow，仅用于读取操作系统剪贴板中的位图。终端的 Ctrl+V 只会传输"文本"，不会把剪贴板图片送进 TUI，因此必须直接读系统剪贴板；为避免被终端拦截，使用独立按键（如 Ctrl+Shift+V）以及斜杠命令作为触发，而不是普通 Ctrl+V。Pillow 缺失时降级为友好提示，不阻断其他功能。
- 统一输入类型：全程使用 `list[Block]`（图片为已有 `ImageBlock`，文本为 `TextBlock`），`str` 入参保留兼容。不新增图片数据类型，复用已验证的序列化与协议转换。

## 2. 实现策略

- 新建一个附件工具模块，集中负责：文件/图片路径 → 内容块、剪贴板图片 → 内容块、粘贴文本中的路径识别、大小与类型校验。
- 把 `@文件` 的智能识别放在 Agent 的 mention 展开函数里（单一事实来源）：图片扩展名生成图片块，文本文件沿用现有 `<referenced-files>` 文本包装，其他二进制文件生成说明性文本块。
- UI 层维护"待发送附件列表"，提供展示与移除；提交时把文本块与附件块合并成 `list[Block]` 传给 Agent。
- `@文件` 补全逻辑保持原样（仍插入 `@路径` 文本），由 Agent 展开阶段完成智能分流，避免两处重复识别。
- CLI 无头模式新增 `--image` / `--file`（可重复），在调用 Agent 前构建块列表。
- 会话恢复：保留 `--resume <id>` 的现有跨项目精确恢复；不带 id 时弹出文本式会话选择器（列出日期、标题、轮数，输入序号确认）。TUI 的 Ctrl+R 图形选择器已存在，保持不变，避免重复建设。

## 3. 性能与可靠性

- 图片 Base64 在内存中编码，设置与现有 Read 工具一致的单图上限（5MB），总量上限也要限制，避免会话 JSONL 与请求体膨胀。
- 剪贴板只在用户显式触发时读取，不在每次按键或粘贴时轮询。
- 供应商不支持图片时（现有 `supports_images` 判定）给出警告，仍按协议发送，由模型端决定响应。
- 所有文件读取 failures（不存在、权限、过大、非图片伪装）都转为可读提示，不抛未捕获异常。

```mermaid
flowchart TD

    A --> A2[拖放/粘贴文件路径]
    A --> A3[输入 @图片路径]
    A --> A4[CLI --image/--file]
    A1 --> B[附件工具模块: 校验 + 转块]
    A2 --> B
    A4 --> B
    A3 --> C[Agent.expand_mentions: 图片->ImageBlock 文本->TextBlock]
    B --> D[PromptArea 待发送附件列表 + 筹码展示]
    D --> E[handle_submit 合并 text + attachments]
    C --> E
    E --> F[Agent.run 接受 list[Block]]
    F --> G[Session 持久化块]
    F --> H[Providers 转换: Anthropic source.base64 / OpenAI image_url]
    H --> I[模型返回]
```

## 7. 测试要点

- 无头模式用 mock provider 跑通 `--image` / `--file`，断言 Agent 收到含 ImageBlock 的消息。
- 会话写入图片后重新加载，断言 ImageBlock 的 media_type 与 base64 完整。
- `@图片.png` 展开产出 ImageBlock，`@代码.py` 仍产出原 `<file>` 文本。
- `--resume` 无 id 在无 TTY 环境下可回退到"打印列表 + 读取序号"，不挂起。

## Agent Extensions

### SubAgent

- **code-explorer**
- Purpose: 在改动前复核 attach 链路的所有调用点（handle_submit / send_prompt / _agent_worker / agent.run / expand_mentions / replay_session），确认没有遗漏的纯文本假设；改动后再做一次回归式搜索确认无残留。
- Expected outcome: 产出一份"待改调用点清单"与"改动后无遗漏文本假设"的核对结果，避免签名变更造成运行时断裂。
